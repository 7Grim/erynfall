# Scale Specification

**Read this before creating or placing any 3D asset.**

This document defines the canonical scale relationships used throughout the Erynfall world and rendering pipeline. All constants are centralized in `client/src/main/java/com/osrs/client/WorldScale.java`.

---

## Core Identity

**1 gameplay tile = 1.0 world unit (WU)**

This is the foundational identity of the pipeline. It is not a multiplier — the server sends integer tile coordinates and the client maps them directly to world-unit positions (no conversion, no scaling). A tile at server position `(x, y)` is rendered with its bottom-left corner at world position `(x, 0, y)` and its bottom-right corner at `(x+1, 0, y+1)`.

| Concept | Value | Unit |
|---|---|---|
| 1 tile | 1.0 | world units |
| Tile grid step | 1.0 | WU |
| Tile center offset | +0.5 in X and Z | WU |
| Ground plane (Y) | 0.0 | WU |

---

## Player / NPC Scale

| Concept | Value | Source |
|---|---|---|
| Canonical height | **1.80 WU** | `WorldScale.PLAYER_HEIGHT` |
| Placement origin | tile-center bottom | `(tileX+0.5, groundY, tileY+0.5)` |
| Manifest scale | 1.0 | `manifest.yaml` → `scale: 1.0` |

All player and NPC character models **must be normalised to 1.80 WU** before export. This is enforced by `scripts/legacy/convert-glb-to-player.py` (`normalise_to_180cm`).

Equipment anchor heights (world units above tile ground, from `Renderer3DExperimental.java`):

| Anchor | Y offset |
|---|---|
| `feet_anchor` | 0.08 |
| `legs_anchor` | 0.38 |
| `body_anchor`, `weapon_anchor`, `shield_anchor`, `hands_anchor` | 0.82–0.84 |
| `ammo_anchor` | 0.92 |
| `head_anchor` | 1.18 |

## Terrain

### Flat ground
Ground plane is at `Y = 0.0` (`WorldScale.GROUND_Y`).

### Elevation
Terrain uses integer elevation levels. Each level adds `0.6 WU` vertically:

```
worldY = level * WorldScale.TERRAIN_HEIGHT_STEP_DEFAULT   // 0.6 WU per level
```

This default can be overridden per-scene via `terrain_height.height_step` in `scene.yaml`.

### Procedural tile walls
Walls generated procedurally from the tile map reach `WorldScale.TERRAIN_WALL_HEIGHT = 1.2 WU`. This is intentionally **shorter than player height (1.80 WU)** so players can see over low dividers — consistent with OSRS visibility conventions.

## Static Props

**Rule: 1 Blender unit = 1 WU = 1 tile.**

| Parameter | Value |
|---|---|
| Blender origin | bottom-center of object at `(0, 0, 0)` |
| Manifest `scale` | `1.0` |
| Manifest `origin` | `tile-center` |
| Placement rotation | Y-axis only |

A prop that is 1 Blender unit wide will occupy exactly 1 tile when placed. A barrel that is 0.6 BU tall will be 0.6 WU tall in-game (one-third of player height — reasonable for a barrel).

---

## Building Shells — Exception Case

Building shells **do not follow the 1:1 rule**. They are authored at a reduced internal scale and expanded via a placement `scale` multiplier in `scene.yaml`.

### Why the exception exists
Building shells must cover multiple tiles. Authoring them at 1:1 would produce very large Blender files with integer-unit geometry. Instead, they are modelled at roughly `~2× model units` extents and then scaled up on placement.

### Model geometry (from `scripts/gen_osrs_buildings.py`)

| Variant | Half-width (BU) | Half-depth (BU) | Wall height (BU) |
|---|---|---|---|
| `small` | 2.10 | 1.90 | 1.50 |
| `service` | 2.50 | 2.10 | 1.55 |
| `coastal` | 2.10 | 1.90 | 1.25 |

### Placement scales used in `main_world/scene.yaml`

Scales observed: **1.4×, 1.5×, 1.6×, 1.8×, 2.0×, 2.5×**

### Resulting in-game dimensions (at common scales)

| Model | Scale | Width (WU/tiles) | Depth (WU/tiles) | Wall height (WU) |
|---|---|---|---|---|
| small | 1.5× | 6.3 | 5.7 | 2.25 |
| small | 2.5× | 10.5 | 9.5 | 3.75 |
| service | 2.0× | 10.0 | 8.4 | 3.10 |
| coastal | 1.5× | 6.3 | 5.7 | 1.88 |

### Workflow for placing a building shell
The scene.yaml comments document each building's effective footprint in tiles, derived from:
```
effective_half_width_tiles = model_hw × placement_scale
effective_full_width_tiles = effective_half_width_tiles × 2
```

## Two Wall Systems — Do Not Confuse

| System | Height | Generated by |
|---|---|---|
| Procedural terrain walls | 1.2 WU (`WorldScale.TERRAIN_WALL_HEIGHT`) | Tile map data (tile type = WALL) |
| Building shell walls | 1.88–3.75 WU (varies with scale) | GLB models placed in `scene.yaml` |

These are completely separate systems. `TERRAIN_WALL_HEIGHT` has no effect on building model heights.

## Walk Speed / OSRS Tick (Not a Scale Value)

The OSRS tick is **0.6 seconds**. One tile of movement takes one tick:

```java
// GameScreen.java
private static final float TILES_PER_SECOND = 1.0f / 0.6f;  // OSRS: 1 tile/tick
```

`0.6` also appears as `WorldScale.TERRAIN_HEIGHT_STEP_DEFAULT` (world units per elevation level). **These are coincidentally equal numbers representing completely different things** — do not combine or confuse them.

## 2D Fallback Renderer (F9 toggle)

The 2D isometric fallback renderer uses pixel-based constants that are unrelated to 3D world units:

| Constant | Value | Meaning |
|---|---|---|
| `CoordinateConverter.TILE_WIDTH` | 32 px | Screen width per tile in 2D view |
| `CoordinateConverter.TILE_HEIGHT` | 16 px | Screen height per tile in 2D view |

These apply only when the 2D renderer is active and have no bearing on 3D world positions.

## Known Inconsistencies

### 1. Player height: 1.80 vs. 2.0
The building-shell generator (`scripts/gen_osrs_buildings.py`) was calibrated against a player model assumed to span `Y: ±1.0` (height = **2.0 WU**). The canonical player height is **1.80 WU**. This means building walls are rendered ~11% taller relative to the player than the proportion comments in the script imply. Not a visual problem in practice (walls are still "taller than the player"), but the comments in the script are misleading.

**Resolution**: Accept the current proportions. Update the comment in `gen_osrs_buildings.py` to reference `WorldScale.PLAYER_HEIGHT = 1.80` and note the 11% offset.

### 2. GRAPHICS_STYLE.md prop rule doesn't cover buildings
`docs/GRAPHICS_STYLE.md` (line 275) states "Scale: 1 tile = 1 world unit" for static props, but this does not apply to building shells (which use placement scale multipliers). The rule is accurate for single props; it's just incomplete. **This document is the authoritative clarification.**

### 3. Unused `GROUND_Y` constant in renderer
`Renderer3DExperimental.java` declares `GROUND_Y = WorldScale.GROUND_Y` but never uses it — ground Y = 0 is used inline throughout. Not harmful; keep for documentation value.
